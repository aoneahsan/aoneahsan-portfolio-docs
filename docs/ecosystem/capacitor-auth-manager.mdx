Capacitor Auth Manager is a package I can inspect as code and on npm. Its current public contract offers one Google sign-in call for web, Android and iOS.

**The question:** How much sign-in code should three app targets share?

## What does the package put behind one call?

The package spans a browser and two native app targets. That gives a product team one public entry point for Google sign-in while the platform behaviour remains inside the package.

## What dependency does it avoid?

Firebase is not required as a dependency. That is a concrete integration boundary, not a promise about every application that might use the package.

## Which provider is actually present?

Google is the only enabled provider in version 3.x. I would rather name the available path than imply a menu of providers that the release does not contain.
