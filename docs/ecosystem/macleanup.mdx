macleanup carries a macOS section catalogue and a real dry run. Its published boundary is unusually clear: personal folders are refused unconditionally.

**The question:** Which folders should a maintenance tool refuse?

## What appears before removal?

A person can preview the sections and run a dry run before changing the machine. That gives them a chance to read the proposed work.

## What is excluded?

Personal folders are outside the tool’s permitted targets. I would treat that as an implementation rule to verify, not a line of reassuring copy.

## Where can it be inspected?

The public repository shows the current macOS tool.

## How would I test its narrow promise?

I would inspect the current section catalogue, run a dry run and look at the paths it proposes. Personal folders are outside the permitted targets unconditionally, so that exclusion is a behaviour to prove, not a reassuring label to add after the fact. The product is for macOS, and the public repository is a place to read how its current release handles those decisions. A preview also gives a person time to stop before any removal. The portfolio should not imply that every file called a cache is disposable. The useful promise is the specific boundary the tool enforces.

The real test is whether a proposed path outside that boundary is refused, even when a section name makes it look routine.

- The same section catalogue, for macOS
