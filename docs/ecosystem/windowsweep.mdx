windowsweep is a Windows cleanup command line and desktop app. It names paths before touching them, has 30 sections and runs a real dry run without network calls.

**The question:** What should a Windows cleanup receipt tell you?

## What happens before a delete?

A dry run lists what would be touched. Personal files are chosen row by row, so a broad category is not treated as blanket permission.

## How can it be run?

The published routes include npx windowsweep and a Windows desktop app. The command line needs no separate installer for the npx path.

## What is the trust boundary?

The documented dry run names paths and makes no network calls.

## What does a receipt need to explain?

Before removal, windowsweep names paths and runs a dry run across its thirty sections. Personal files are chosen row by row. That turns a broad cleanup label into a list a person can read and refuse. I would compare a proposed run with the result and check that the no-network boundary remains true for the local tool. The recorded release routes are an npx command and a Windows desktop app; both should make the proposed work legible before a real change. A convenient launcher is useful, but the path list and the user's choice are the parts that earn trust.

## From the release record

- Windows cleanup CLI: dry-run first, personal files chosen row by row, zero install via npx.
- Names every path before it touches one
- 30 sections, a real dry-run, and no network calls
- Runs as npx windowsweep or as a Windows desktop app
