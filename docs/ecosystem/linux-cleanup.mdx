**The question:** What can a cleanup tool show before deletion?

## What can be previewed?

The desktop app shows cache paths and its boundaries before a person runs a removal. The command line has scan and dry-run commands that never delete.

## What ships on Linux?

The roster records an x86_64 desktop app distributed as AppImage and .deb, plus an MIT-licensed command line available through npx. A real removal produces a receipt.

## Which promise is deliberately narrow?

The dry run is a preview, not permission to delete personal files. A cleanup product is credible when the exact path and consequence are visible before a click.

## What should a dry run earn?

A readable account of the paths that a real run would touch. The desktop app names cache paths and limits, while its command line provides scan and dry-run commands that do not delete. After a real run, a receipt records what happened. I would inspect a dry run before choosing any removal, then compare its promised paths with the receipt rather than relying on a broad word such as cleanup. The x86_64 AppImage, .deb and npx command line are all recorded release routes. None of those formats changes the central rule: a preview must be useful before an irreversible action.
